# Лабораторна робота № 1 — Механізми захисту ОС Windows

Матеріали до ЛР №1 «Механізми захисту операційної системи Windows».

Коду немає — лише налаштування Windows. Суть: написати коротку політику безпеки,
створити користувачів і групи, роздати права на файли, перевірити доступ під кожним
і показати події в журналі.

---

## 0. Що потрібно

- **Windows 11 Pro** у віртуальній машині (Hyper-V).
- Адміністратор + можливість створювати локальних користувачів.
- Диск **NTFS** (за замовчуванням так і є).

> Роби все у ВМ. На основній Windows краще не експериментувати з ACL і аудитом.

---

## 1. Політика безпеки (для звіту, 5 хвилин тексту)

Задай неформально, наприклад:

**Групи**
- `Developers` — повний доступ до `C:\Project\Source`, читання `C:\Project\Docs`
- `Testers` — зміна в `C:\Project\Tests`, читання `C:\Project\Source`

**Користувачі**
- `dev1`, `dev2` → група Developers
- `tester1` → група Testers

**Паролі:** мін. 8 символів, складність увімкнена, блокування після 3 невдалих спроб.

**Аудит:** успішні й невдалі входи; для важливих файлів — аудит видалення / зміни прав.

3. Те саме для **Система** (за бажанням)

## 3. Парольна політика та блокування

1. `Win+R` → `secpol.msc`
2. **Політики облікових записів → Політика паролів**
   - Мінімальна довжина: **8**
   - Пароль має відповідати вимогам складності: **Увімкнено**
   - Зберігати історію паролів: **5** (або більше)
3. **Політика блокування облікового запису**
   - Поріг блокування: **3**
   - Тривалість блокування: **30** хвилин
4. **Локальні політики → Політика аудиту**
   - Аудит входу в систему: **Успіх + Відмова**
   - Аудит доступу до об’єктів: **Успіх + Відмова** (потрібно для аудиту файлів)

## 4. Користувачі та групи

1. `Win+R` → `lusrmgr.msc`  
   (якщо немає — Параметри → Облікові записи → Інші користувачі, або `compmgmt.msc`)
2. **Групи → Створити**: `Developers`, `Testers`
3. **Користувачі → Новий користувач**:
   - `dev1` / пароль `Dev1pass!`
   - `dev2` / пароль `Dev2pass!`
   - `tester1` / пароль `Test1pass!`
4. Додай `dev1`, `dev2` у `Developers`; `tester1` у `Testers`
5. Зніми «Користувач повинен змінити пароль…», постав «Термін дії пароля не обмежений» (для зручності лаби)

## 5. Структура папок і 6+ файлів

Створи (під адміном):

```
C:\Project\
  Source\     created_by_dev.txt
  Tests\      plan1.txt
  Docs\       Documentation.txt
  Shared\     readme.txt
  Private\    admin_only.txt
  Logs\       access.log
```

Швидко в PowerShell (від адміна):

```powershell
New-Item -ItemType Directory -Force -Path C:\Project\Source, C:\Project\Tests, C:\Project\Docs, C:\Project\Shared, C:\Project\Private, C:\Project\Logs | Out-Null
"dev file" | Set-Content C:\Project\Source\created_by_dev.txt
"test plan" | Set-Content C:\Project\Tests\plan1.txt
"docs" | Set-Content C:\Project\Docs\Documentation.txt
"shared" | Set-Content C:\Project\Shared\readme.txt
"secret" | Set-Content C:\Project\Private\admin_only.txt
"log" | Set-Content C:\Project\Logs\access.log
```

## 6. ACL (права) — головне

Для кожної папки: ПКМ → **Властивості → Безпека → Змінити / Додатково**.

Рекомендована схема (достатньо для звіту):

| Об’єкт | Developers | Testers | Users / інші |
|--------|------------|---------|--------------|
| `Source\` + файл | **Повний доступ** | Читання й виконання | Прибрати зайве |
| `Tests\` + файл | Читання | **Зміна** | Прибрати зайве |
| `Docs\Documentation.txt` | Читання | Читання | — |
| `Shared\readme.txt` | Зміна | Читання | — |
| `Private\admin_only.txt` | Немає | Немає | лише Administrators |
| `Logs\access.log` | Читання | Читання | Administrators — повний |

Порада: у **Додатково** вимкни успадкування («Вимкнути успадкування» → «Перетворити…»), потім додай потрібні групи вручну — інакше `Users` може все ще мати права.

Для `Documentation.txt` додатково: **Додатково → Аудит → Додати** → принципал `Everyone` → тип Усі → познач **Видалення** і **Зміна дозволів**.

## 7. Перевірка доступу (протокол)

Послідовно вийди й зайди під кожним користувачем (або `runas`, або швидке перемикання).

| № | Хто | Дія | Очікування |
|---|-----|-----|------------|
| 1 | `dev1` | Створити/змінити файл у `Source` | Успіх |
| 2 | `dev1` | Створити файл у `Tests` | Відмова |
| 3 | `tester1` | Змінити `plan1.txt` у `Tests` | Успіх |
| 4 | `tester1` | Змінити `created_by_dev.txt` у `Source` | Відмова |
| 5 | `tester1` | Відкрити `admin_only.txt` | Відмова |
| 6 | `dev1` | 3× невірний пароль при вході | Блокування (якщо політика діє) |

Фіксуй скріни помилок «Відмовлено в доступі».
